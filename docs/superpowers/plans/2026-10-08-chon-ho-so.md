# Chọn hồ sơ khách hàng Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Khách chọn / chuyển hồ sơ khách hàng (mọi công ty) sau khi đăng nhập; mọi màn theo hồ sơ đang chọn.

**Architecture:** Phiên `cloud_portal_sessions` nhớ `khach_hang_id`; `_portal_session` trả hồ sơ phiên (fallback tài khoản) → hàm yêu cầu / thanh toán tự theo. App dựng danh sách hồ sơ từ `fn_portal_app_ho_so_list` mỗi công ty, chọn qua `fn_portal_app_chon_ho_so`.

**Tech Stack:** PostgreSQL plpgsql (Supabase self-host), Expo Router + RN + TS, `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-08-chon-ho-so-design.md`

## Global Constraints
- Không đổi hành vi web: `_portal_session` chỉ thêm `COALESCE(s.khach_hang_id, a.khach_hang_id)`; phiên web không đặt cột.
- Lỗi RPC trả `{error}`; câu lỗi đúng spec.
- App: token theme, `<Text variant>`, không import `data/mock` ngoài services; tiếng Việt.
- App repo không commit (việc dở của người dùng trên `main`); `beeland` commit trên `devhuan`.

## Review Focus
- Phiên cũ lưu trước thay đổi (không có `profiles`) → vẫn chạy, coi 1 hồ sơ.
- `fn_portal_app_ho_so_list` lỗi (migration chưa áp) → đăng nhập vẫn được, chỉ 1 hồ sơ.
- Hồ sơ ở công ty khác cùng SĐT không lọt vào danh sách của công ty này.
- Chọn hồ sơ ở công ty khác công ty đang xem → đổi cả công ty + gọi chọn trên token công ty đó.
- Đổi hồ sơ → bộ nhớ đệm dữ liệu xoá, màn dựng lại (key gồm customerId).
